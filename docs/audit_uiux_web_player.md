## 3. Ranked Evidence-Backed Findings

### Critical / Blockers (Must Fix Before Ship)

#### WP-CRIT-01 — Mobile (`390×844`) Video Player Control Bar Overflows & Clips `Settings`, `PiP`, and `Fullscreen` Off-Screen
- **Category:** Player UX · Responsive Layout · Touch Ergonomics (UI/UX Pro Max Priority 2 & 5)
- **Live Observation:** On `390×844` iPhone viewport (`videoRect`: `374×210px`, right edge at `x = 382px`), tapping the video reveals a single non-wrapping bottom flex row (`flex items-center justify-between gap-2`). Because the left group renders `[Play 32px]`, `[-10s 54px]`, `[+10s 55px]`, `[Mute 28px]`, and an unhidden **`64×6px` desktop volume `<input type="range">`** (`x=220`), the right-side controls are pushed past the `overflow-hidden` video boundary:
  - `Cài đặt` (Settings gear): `x = 366px, w = 34px` (`x_right = 400px > 382px` — **sliced in half** at the frame edge).
  - `PiP`: `x = 406px, w = 28px` (**100% off-screen**, unreachable).
  - `Fullscreen`: `x = 440px, w = 28px` (**100% off-screen**, unreachable).
  - Mobile viewers on standard `375–390px` phones **cannot enter Fullscreen or open Quality/Subtitle Settings**.
- **Root Cause:** [VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L3821-L3900) (`flex-shrink-0` on both left and right control groups inside `overflow-hidden` container at [VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L3181)), volume range input `w-16 sm:w-20` not hidden on mobile ([VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L3884)), and `-10s`/`+10s` text labels kept visible on `< 640px` ([VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L3846-L3858)).
- **Evidence:** [19_mobile_watch_player.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/19_mobile_watch_player.png) · `mobilePlayerErgonomics` in [telemetry_summary.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/telemetry_summary.json)
- **Fix:** Hide the inline volume slider on touch/mobile viewports (`hidden sm:block` on the `<input type="range">`, since iOS/Android manage hardware volume or vertical swipe HUD), hide `-10s`/`+10s` text spans below `sm:` (keep icons or rely on existing double-tap left/right gesture), remove duplicate bottom `PiP` button on mobile, and ensure all remaining primary player controls (`Play`, `Mute`, `Next Ep`, `Episodes`, `Settings`, `Fullscreen`) have `min-w-[44px] min-h-[44px]` touch hit areas inside `375px`.

#### WP-CRIT-02 — Multi-Server Failover & Backup Server Switching Completely Broken End-to-End
- **Category:** Functional Bug · Streaming Reliability
- **Live Observation:** In SQLite (`movies.db`), `spider-man-brand-new-day` has **3 configured servers** (`Server VIP (4K CDN)`, `Server 2 (Dự Phòng)`, `Server 3 (Direct CDN)`) and `jurassic-park` has **2 servers**. During live E2E testing on `/watch/spider-man-brand-new-day`, Server 0 (`/api/stream/spider-man-brand-new-day/master.m3u8`) returned HTTP `403 Forbidden` across 3 attempts (`retryCountRef` 0 → 2) and landed on `"Không thể phát video từ nguồn này. [Thử lại]"`. Zero server-switch buttons were rendered anywhere on the Detail page or Watch page (`serverButtonsFound: []`, `hasServerSwitcherOnPage: false`), leaving the user completely stranded with no way to switch to `Server 2 (Dự Phòng)` or `Server 3`.
- **Root Cause (Three Compounding Bugs):**
  1. **Adapter Truncation (Single Movies):** [api.ts](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/api.ts#L268-L270) explicitly slices only the first server: `const serversList = Array.isArray(raw.servers) && raw.servers.length > 0 ? [raw.servers[0]] : [null];` — discarding `raw.servers[1..n]`.
  2. **Adapter Truncation (TV Series):** [api.ts](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/api.ts#L209-L264) pushes only `[raw.episodes[0]]` (line 210) or builds only a single `Server VIP #1` group from `ep.servers?.[0]` (lines 233, 261–264), discarding all backup episode servers (`ep.servers[1..n]`).
  3. **WatchPage / EpisodeSelector Hides Server Bar on Single Movies:** [WatchPage.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/WatchPage.tsx#L421) wraps `<EpisodeSelector>` in `{!isSingleMovie && ...}` and [EpisodeSelector.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/EpisodeSelector.tsx#L229-L233) returns `null` whenever `isSingle` is true — even though `<EpisodeSelector>` is the **only** component on `WatchPage` that renders the `"Chọn Server / Phiên bản"` switcher! Furthermore, `failPlayback()` in [VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L1981-L1999) has no callback to auto-advance `activeServerIndex` when Server 0 fails.
- **Evidence:** [12_desktop_watch_multiserver_before.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/12_desktop_watch_multiserver_before.png) · [25_desktop_player_error_state.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/25_desktop_player_error_state.png) · `errorStateAfterRetries` in [telemetry_player_deep.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/telemetry_player_deep.json)
- **Fix:** (1) In `api.ts:269`, map over the full `raw.servers` array instead of `[raw.servers[0]]`, and group multi-server TV episodes across `ep.servers` by server index/label with `?server=${idx}`. (2) Decouple `<ServerSelector>` from `!isSingleMovie` so single movies with `servers.length > 1` display server tabs on `WatchPage` (and inside the `playbackError` overlay alongside `"Thử lại"`). (3) Add automatic fallback to `activeServerIndex + 1` in `WatchPage` when `VideoPlayer` reports fatal network error.

#### WP-CRIT-03 — Video Player Elapsed / Duration Timestamp (`00:00 / 47:53`) Is Permanently `display: none` Across All Viewports
- **Category:** Player UX · CSS Configuration Bug
- **Live Observation:** Across Desktop (`1440×900`), Tablet (`768×1024`), and Mobile (`390×844`), the video player control bar never displays the current playback time or total duration (`timestampDisplayComputed: "none"`). Viewers have no persistent time readout while watching a 48-minute episode or 2-hour film.
- **Root Cause:** [VideoPlayer.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/VideoPlayer.tsx#L3890) sets `className="text-xs font-medium text-[#8aa885] ml-1 hidden xs:block"`, assuming an `xs:` breakpoint exists. However, [tailwind.config.js](file:///Users/kuminhdey/Downloads/webproxy/frontend/tailwind.config.js#L4-L30) defines **no `screens.xs` breakpoint**. Tailwind emits `.hidden { display: none }` and silently drops the unknown `xs:block` utility, hiding the timestamp on every screen size.
- **Evidence:** [14_desktop_player_playing.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/14_desktop_player_playing.png) · [21_desktop_player_seek_and_tooltip.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/21_desktop_player_seek_and_tooltip.png) · `realSeekbarTest.timestampDisplayComputed === "none"` in [telemetry_player_deep.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/telemetry_player_deep.json)
- **Fix:** Replace `hidden xs:block` with `block tabular-nums whitespace-nowrap` (using `font-variant-numeric: tabular-nums` per UI/UX Pro Max `number-tabular` so ticking digits never jitter sibling buttons), or define `xs: '420px'` in `tailwind.config.js` while keeping compact `currentTime` visible on mobile.

#### WP-CRIT-04 — Severe Static & Proxied Image Payload Bloat (`1.94 MiB` Logo/Favicons + `17.03 MiB` Poster) & Core Web Vitals CLS Failure (`0.946`)
- **Category:** Performance · Core Web Vitals (Taste Skill `perf.md` & UI/UX Pro Max Priority 3)
- **Live Observation:**
  1. **Uncompressed Brand Assets:** `/logo.png`, `/logo-64.png`, `/favicon.png`, `/favicon-32.png`, and `/favicon.ico` in `frontend/public/` (and built into `frontend/dist/`) are **five identical copies of a `1,983,061`-byte (`1.94 MiB`) PNG**! Because `<Header>`, `<Footer>`, `<link rel="icon">`, and `<MovieCard>` fallback all load `/logo.png` (rendered at `36×36px` to `44×44px`), every session transfers `1.94 MiB` for a tiny `44px` icon (`2.8×` over Taste Skill `perf.md`'s `700 KiB` single-image FAIL cap).
  2. **Unbounded Image Proxy Payload:** One catalog poster served via external CDN (`tiktokcdn.com` PNG) transferred **`17,443,844` bytes (`17.03 MiB`)** for a `192×288px` card thumbnail!
  3. **Severe Cumulative Layout Shift (CLS):** Measured live CLS is **`0.946`** on Tablet Home (`768×1024`), **`0.4496`** on Series Detail, and **`0.4567`** on Watch Page — nearly **`4×` above the `0.25` Core Web Vitals / Taste Skill FAIL limit** (threshold `< 0.1` GOOD). Additionally, `100%` of visible `<img>` elements (`37/37` on Home, `16/16` on Detail, `15/15` on Watch) omit HTML `width` and `height` attributes.
- **Root Cause:** Uncompressed `frontend/public/logo.png` (`1.94 MiB`); [App.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/App.tsx#L291-L297) conditionally mounts `<HeroBanner>` (`h-[460px..600px]`) **only after** `getHome()` resolves without reserving a hero skeleton placeholder while `homeLoading` is true ([App.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/App.tsx#L313-L319)), shoving `<main>` content down by `540px+` on hydration; and [utils.ts](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/utils.ts#L207-L209) proxies raw upstream images without dimension/WebP resizing.
- **Evidence:** `telemetry.desktop.largeAssets`, `tabletHome.perf.cls` (`0.946`), `desktopWatchEp1Real.perf.cls` (`0.4567`) in [telemetry_summary.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/telemetry_summary.json)
- **Fix:** Compress `/logo.png` and `/logo-64.png` to `8–15 KiB` WebP/PNG (`88×88px`), generate true `32×32` `favicon-32.png` (`< 4 KiB`), render a fixed-height `h-[460px] sm:h-[540px] md:h-[600px]` hero skeleton while `homeLoading` is true, and add explicit `width`/`height` attributes plus `decoding="async"` to all `<img>` tags.

#### WP-HIGH-01 — Catalog `"Sắp xếp"` (Sort) Dropdown Is a 100% No-Op due to Frontend/Backend Parameter Mismatch
- **Category:** Functional Bug · Catalog Discovery
- **Live Observation:** Navigating to `/danh-sach/phim-le` and changing `"Sắp xếp"` from `"Mới cập nhật"` (`""`) to `"Tên A-Z"` (`"name_asc"`) produced the **exact same 24-item sequence** (`identicalOrderWhenSortedByNameAsc: true`: `["Godzilla Trừ Không", "Người Nhện: Khởi Đầu Mới", "The Odyssey", "Bát Tiên!", ...]`).

All three UI options fall into the wildcard arm `_ => "ORDER BY year DESC NULLS LAST, score DESC NULLS LAST, id DESC"`.
- **Evidence:** `catalogSortCheck` in [telemetry_player_deep.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/web_player/telemetry_player_deep.json)

#### WP-HIGH-02 — Two of Five Homepage Shelves (`"TV Shows"` & `"Hoạt Hình & Anime"`) Render 100% Duplicate Clones of Earlier Shelves
- **Category:** Functional Bug · Taste Skill `[photo-repeat]` / `[same-object]`
- **Live Observation:** On the live Homepage (`1440×900` & `390×844`), `"PHIM LẺ CHIẾU RẠP"` and `"HOẠT HÌNH & ANIME ĐẶC SẮC"` display the **exact same live-action movies** in identical order (`Bara till jul`, `Thần Y`, `忠臣蔵外伝 四谷怪談`, `Chiết Xuân Uy`, `Địa Đạo Cá Sấu Tử Thần`), even though real anime titles (`Doraemon`, `Shin - Cậu Bé Bút Chì 33`, `Biến tấu Grimm`) exist in the database. Likewise, `"TV SHOWS & GAMESHOW"` duplicates `"PHIM BỘ ĐANG HOT"`.
- **Root Cause:** In [api.ts](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/api.ts#L332), `const allList = (raw.list || []).map(summaryToMovieItem)` converts raw items **before** filtering, and `summaryToMovieItem` ([api.ts](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/api.ts#L120-L137)) strips both `genres` and `movie_type`!
