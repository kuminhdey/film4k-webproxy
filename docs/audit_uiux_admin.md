## 3. Ranked Evidence-Based Findings

### Blockers & Critical Findings

#### ADM-01 [Critical — Broken Ops Controls]: Four Crawler Stage & Warmup Buttons Silently Execute `'latest'` Mode Instead of Their Labeled Operations
- **Observed in Playwright:** Clicking **`Stage 1: Đồng bộ Catalog`**, **`Stage 2: Cào Chi Tiết Đồng Thời`**, **`Stage 3: Quét Cache M3U8`**, and **`Nạp Trước Dữ Liệu Phim Hot`** sends `POST /api/admin/crawler/trigger` with `{ "mode": "stage1_catalog" }`, `{ "mode": "stage2_detail" }`, or `{ "mode": "stage3_m3u8" }`. In live network telemetry ([admin_audit_telemetry.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/admin_audit_telemetry.json#L566-L578)) and terminal screenshot ([12_movies_api_500_error_state.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/12_movies_api_500_error_state.png)), the backend responds `200 OK` with `{"mode": "latest", "message": "Crawler started in 'latest' mode"}` for every single one.
- **Why it fails (Root Cause):**
  1. [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L630-L632) implements `handleWarmupCache` by calling `handleTriggerMode('stage3_m3u8', ...)` instead of calling `POST /api/admin/crawler/warmup` ([admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L579-L602), which is completely orphaned/unused by the frontend) or passing `{ mode: "prewarm" }`.
  2. [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L1654), [L1682](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L1682), and [L1710](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L1710) send `stage1_catalog`, `stage2_detail`, and `stage3_m3u8`.
  3. [admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L622-L627) only accepts `["full", "latest", "prewarm", "force"]` and silently falls back to `"latest"` on any unknown mode string instead of returning `400 Bad Request` or implementing the 3-stage modes in [crawler.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/crawler.rs#L591-L594).
- **Fix:** Either implement `stage1_catalog`, `stage2_detail`, and `stage3_m3u8` in `CrawlerService::run_crawl_mode`, or remove the unimplemented stage buttons so the UI exposes only real supported modes (`full`, `latest`, `prewarm`), wire `"Nạp Trước Dữ Liệu Phim Hot"` to `POST /api/admin/crawler/warmup`, and return `400 Bad Request` for unrecognized `TriggerRequest.mode` values.

#### ADM-02 [Critical — Missing Catalog CRUD & Ops Controls]: Admin Catalog Is Read-Only (No Create/Edit/Delete Movie or Episode CRUD, No Column Sorting, Unreachable Global Cache Clear)
- **Observed in Playwright:** Probing the UI and backend against `/tmp/audit_admin_test.db` ([admin_audit_telemetry.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/admin_audit_telemetry.json#L470-L508)):
  - `POST /api/admin/movies` → `405 Method Not Allowed`
  - `PUT /api/admin/movies/:slug` → `405 Method Not Allowed`
  - `DELETE /api/admin/movies/:slug` → `405 Method Not Allowed`
  - Zero UI controls exist for creating a movie, editing movie metadata/streams/episodes, or deleting a catalog entry.
  - All 5 table headers (`Phim`, `Loại & Thể loại`, `Năm`, `Trạng Thái Cache M3U8`, `Hành Động`) are static `<th>` elements (`aria-sort: null`, not clickable) even though the backend query engine already supports `?sort=latest|score|views|year` ([db.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/db.rs#L907-L913)).
  - Global cache purge (`POST /api/admin/cache/clear`) is implemented in [admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L671-L751) and registered in [lib.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/lib.rs#L105), yet has **no button in `AdminDashboard.tsx`**.
  - `filterType` state in [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L132) declares `'all' | 'movie' | 'tv' | 'cached' | 'uncached'`, but only 3 tabs (`Tất cả`, `Phim lẻ`, `Phim bộ`) are rendered ([L2018-L2024](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L2018-L2024)) and `filteredMovies` ([L719-L725](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L719-L725)) redundantly re-filters client-side without handling `cached`/`uncached`.
- **Fix:** Add authenticated `POST /api/admin/movies`, `PUT /api/admin/movies/:slug`, and `DELETE /api/admin/movies/:slug` handlers in `admin.rs` + `db.rs` with input validation, pair them with an accessible Create/Edit Movie + Episode drawer/modal and guarded Delete Movie confirmation dialog, wire sortable `<th>` buttons (`aria-sort`) to `?sort=`, and expose a confirmation-guarded `"Xóa Toàn Bộ Cache M3U8"` button wired to `POST /api/admin/cache/clear`.

#### ADM-03 [Critical — False-Positive Error Handling & Unprotected Destructive Action]: Per-Movie `"Xóa Cache"` Reports Success on HTTP 500 and Lacks Confirmation/Undo
- **Observed in Playwright:**
  1. Clicking `"Xóa Cache"` immediately purges `/tmp/audit_admin_playlists/visionquest` on a single click with no confirmation prompt or undo option.
  2. When `/api/admin/cache/clear/visionquest` returns **HTTP 500** (`{"success": false, "error": "Simulated disk permission error EACCES"}`), `handleClearMovieCache` logs `[SUCCESS] Đã xóa sạch cache M3U8 của visionquest` to the server log stream and triggers a green checkmark success toast instead of surfacing the error ([admin_audit_telemetry.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/admin_audit_telemetry.json#L612-L621)).
- **Why it fails (Root Cause):** In [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L689-L700), `handleClearMovieCache` checks `if (res.status === 401 || res.status === 403) return;` and then unconditionally executes `addLog('success', ...)` and `showToast('🗑️ Đã xóa cache M3U8: ...')` **without checking `if (!res.ok || data.success === false)`**! Additionally, the toast component ([AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L976-L1001)) hardcodes `<CheckCircle2 size={18} color="#10b981" />` (emerald success icon) even when displaying warning or error toasts (`⚠️` / `❌`).
- **Fix:** Check `if (!res.ok || data.success === false) throw new Error(data.error || data.message || \`HTTP \${res.status}\`);` in `handleClearMovieCache`, display an error-variant toast (`role="status"` / `aria-live="polite"`, semantic error icon & border), and guard destructive cache purges with confirmation or inline 2-step confirm (`"Xác nhận xóa?"`).

#### ADM-04 [High — Broken Table Telemetry]: 100% of Admin Table Rows Permanently Display `"Chưa có cache"` Even When M3U8 Cache Exists
- **Observed in Playwright:** Pre-seeding valid `#EXTM3U` `master.m3u8` directories for `visionquest` and `street-fighter` inside `PLAYLISTS_DIR` caused Card 2 (`cached_m3u8_count`) to report `3`, yet **0 of 17 rows** in the Admin table displayed `"Có mục playlist cache"` — both `visionquest` and `street-fighter` rendered `"Chưa có cache"` ([04_dashboard_overview_desktop_1440x900.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/04_dashboard_overview_desktop_1440x900.png), [11_false_success_toast_on_500.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/11_false_success_toast_on_500.png), [admin_audit_telemetry.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/admin_audit_telemetry.json#L509-L511)).
- **Why it fails (Root Cause):** [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L467) normalizes `has_cached_m3u8: Boolean(m.has_cached_m3u8)`, but `admin_movies` ([admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L461-L483)) serializes `Vec<MovieSummary>` ([models.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/models.rs#L202-L217)), which **has no `has_cached_m3u8` field**. `m.has_cached_m3u8` is always `undefined`.
- **Fix:** Enrich `admin_movies` response items in [admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L473-L477) by checking `state.playlist_cache.master_path(&m.slug).exists()` and SQLite `playlist_cache` presence per returned movie slug.

#### ADM-05 [High — Telemetry Inaccuracy]: Disk Usage Reports `DB: 0 B` Under Custom `DATABASE_PATH` & Card 2 Mislabels Directory Count as SQLite Cache
- **Observed in Playwright:** With `DATABASE_PATH=/tmp/audit_admin_test.db` (`475 KB` SQLite file) and 3 playlist directories (`279 B`), `/api/admin/stats` returned `"database_bytes": 0, "playlists_bytes": 279, "human_readable": "279 B"` ([04_dashboard_overview_desktop_1440x900.png](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/04_dashboard_overview_desktop_1440x900.png), [admin_audit_telemetry.json](file:///Users/kuminhdey/Downloads/webproxy/docs/audit_artifacts/admin/admin_audit_telemetry.json#L378-L383)). Meanwhile, Card 2 is titled `"PLAYLIST CACHE TRONG SQLITE"` and shows `3` even though `SELECT COUNT(*) FROM playlist_cache` in SQLite is `0`.
- **Why it fails (Root Cause):**
  1. `find_db_size()` in [admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L825-L841) ignores `std::env::var("DATABASE_PATH")` (used by [main.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/main.rs#L24)) and only checks hardcoded paths `["movies.db", "data/movies.db", "../movies.db", "/app/movies.db"]` (and excludes `-wal` file bytes). In Docker (`DATABASE_PATH=/app/data/movies.db` or custom volume), `database_bytes` silently reports `0 B`.
  2. `admin_stats` ([admin.rs](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L419), [L437](file:///Users/kuminhdey/Downloads/webproxy/backend/src/admin.rs#L437)) sets `cached_m3u8_count` from `count_cached_playlists(&base_dir)` (filesystem subdirectories), whereas [AdminDashboard.tsx](file:///Users/kuminhdey/Downloads/webproxy/frontend/src/components/AdminDashboard.tsx#L1289-L1310) labels it `"Playlist cache trong SQLite"`.
- **Fix:** Check `std::env::var("DATABASE_PATH")` (including `.db-wal` size) first inside `find_db_size()`, and return separate `sqlite_playlist_cache_count` and `disk_playlist_dirs_count` fields in `AdminStatsResponse` with accurate labels.
